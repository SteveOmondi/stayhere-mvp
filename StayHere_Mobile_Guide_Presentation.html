🏗 Architecture

API Services

All services are fronted by Azure API Management (APIM). Prefix every endpoint with the base URL below.

https://apim-dev-5c27bcf3.azure-api.net
Auth Service
/auth → /auth/signup, /auth/login, /auth/verify-otp
OTP-based passwordless login · JWT tokens
Property Service
/property → /listings, /bookings, /applications, /upload
Listings, rental flow, document upload, terms, payments
Customer Service
/customers → /customers/{id}
Customer profile, saved properties, rented properties
AI Agent Service
/aiagent → /aiagent/chat, /aiagent/listings
Sage AI chat + semantic property search
Static Data Service
/staticdata → /counties, /amenities, /property-types
Drop-down / filter reference data
🔐 Auth Flow
1. POST /auth/signup (once)
2. POST /auth/login → OTP sent via email
3. POST /auth/verify-otp → JWT
4. Store token, userId, role
5. Check role === "Tenant" — reject others
6. Attach Authorization: Bearer <token>
📦 Token Storage
Store JWT securely using flutter_secure_storage (Flutter) or Keychain/Keystore. Never store in plain SharedPreferences. Include customerId from verify-otp response for all customer-specific calls.
🌐 Request Headers
Authorization: Bearer <jwt> Content-Type: application/json Accept: application/json

Resume Logic
From My Applications, users can continue any in-progress application.

Resumable statuses:
• DocumentsPending → Step 3

⚠️ Critical

Business Rules — Must Implement

These rules are enforced by the API. Violating them will cause errors or data corruption.

🔐
Tenant-Only Access
After verify-otp, check role === "Tenant". If Admin, PropertyOwner, or PropertyManager — show error and block entry. Do not store the token.
📋
Sequential Flow
Users MUST complete steps in order: Booking → Application → Docs → Terms → Payment. The API rejects out-of-order actions.
📤
R2 Upload — Content-Type
The PUT to R2 MUST use the exact contentType returned in the presigned URL response. A mismatch causes a 403 from Cloudflare (SigV4 signature includes the Content-Type).
📞
M-Pesa Phone Format
Send phone as 254XXXXXXXXX — no + prefix, no spaces. Convert 07XXXXXXXX → 2547XXXXXXXX before submitting.
🔄
Payment Polling
Poll /payment/status every 4 seconds max after initiating STK Push. Stop when status is Completed or Failed. Show spinner + "Check M-Pesa on your phone".
🔑
Pascal-Case Auth Fields
Login and verify-otp require Email and PhoneNumber (Pascal-case). Lowercase versions are silently ignored by the API, causing unexpected 400 errors.
🔁
Resume Applications
Always check for existing in-progress applications before starting a new one for the same listing. Prompt the user to continue or abandon the existing one.
🖼
Image Loading
R2 public images need no auth headers. Use primaryImageUrl first, fallback to images[0]. Cache images locally — same URL = same file (content-addressed).
🛡 Error Handling

Common Errors & How to Handle

The API returns standard HTTP status codes. Map these to user-friendly messages in the app.

401 Unauthorized
Token expired or missing. Clear stored token and redirect to Login screen. Implement token refresh check on app resume.
400 Bad Request
Validation error — usually missing field or wrong format. Show the error message from the response body. Common cause: lowercase auth fields or missing bookingId.
409 Conflict
Duplicate record — e.g., email already registered, or application already exists for that listing. Show "You've already applied" message with option to view existing application.
403 R2 Upload Fail
Content-Type mismatch in the PUT request. Ensure you use exactly the contentType from the presigned URL response, not the file's MIME type independently.
Payment Failed
M-Pesa STK timeout (user didn't approve in 30s) or insufficient funds. Show clear message, offer "Try Again" which re-initiates the STK Push — no new application needed.
Network / 5xx
Implement exponential backoff with 3 retries for GET requests. For POST/PATCH — check idempotency before retry to avoid duplicate applications or payments.
